08

ACID Transactions

A
AtomicityAll participating database changes commit together or roll back together.
C
ConsistencyA committed transaction preserves database integrity rules.
I
IsolationControls how concurrent transactions interact.
D
DurabilityCommitted changes are intended to survive failures according to database durability guarantees.
BANK TRANSFER · ONE TRANSACTION
BEGIN→ Account A: -100 SAR→ Account B: +100 SAR→ COMMIT
The debit and credit should be handled as one correctly designed database transaction. If any step fails → ROLLBACK: neither change is kept, so money is never lost or created.
09

Banking Database Reminders

Transactions

@Transactional groups participating database operations. It does not automatically roll back an external payment-provider operation.

Concurrency

Use appropriate locking, atomic conditional updates, and database constraints to protect critical financial rules.

Indexes

Indexes can improve suitable read queries but consume storage and add write overhead. Choose them based on query patterns and execution plans.

Sample schema: Customer(customer_id PK, name) · Account(account_id PK, customer_id FK → Customer, balance) Logical query order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
